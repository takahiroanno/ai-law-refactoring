# アナログ規制の「概念ベース」洗い出し

デジタル臨時行政調査会のアナログ規制一括見直し（フロッピーディスク・「対面」等の**キーワード検索→一括改正**）を一歩進め、
**特定の単語には現れないが条文の「書かれ方」そのものがアナログ前提になっている箇所**を、
概念（コンセプト）単位で現行法から機械的に洗い出す試み。

## 手法（3層パイプライン）

```
① 概念カタログ設計          concepts.json     … アナログ前提の「書かれ方」を18概念に体系化
② 全法令スキャン            scan_concepts.py  … 現行法律2,100本・96,780条に候補網（正規表現）を適用
③ LLM判定                   （並列エージェント）… 候補の真陽性判定＋候補網に載らない新概念の発見
```

- データソース: e-Gov法令XML（法令標準XML）。`laws.e-gov.go.jp` へのAPI直接アクセスが本セッションの
  ネットワークポリシーで遮断されていたため、e-Gov の `all_xml.zip` を法令ごとの current.xml に展開した
  GitHubミラー [aluqas/gitlaw-jp](https://github.com/aluqas/gitlaw-jp)（2025年5月時点・**法律のみ2,100本**）を使用。
- 対象は本則のみ（附則は経過措置中心のため除外）。**政令・省令は未収録**（アナログ規制の物量は省令層に多いので、
  e-Gov API v2 が使える環境で同じパイプラインを全法令種別に回すのが次の一手）。
- 各条文について「電磁的方法／電子情報処理組織等のデジタル代替規定」の有無を条レベル・法令レベルで併記。
  **代替規定が皆無の法令ほど優先ターゲット**になる。

## ① 概念体系：どういう「書かれ方」がアナログ前提か

デジタル庁の7類型（目視／実地監査／定期検査・点検／常駐・専任／対面講習／書面掲示／往訪閲覧・縦覧）＋
フロッピーディスク条項を出発点に、キーワードに還元されない書かれ方まで18概念に拡張した（詳細は `concepts.json`）。

| # | 概念 | 典型的な書かれ方（キーワードに現れない例） | 障壁になる理由 |
|---|------|------|------|
| C01 | 対面・出頭・物理的同席 | 「〜の**面前で**」「**立会い**をもってしなければ効力を生じない」「出頭を命ずる」 | オンライン面談・遠隔立会いを排除する解釈の根拠に |
| C02 | 実地・現地・目視確認 | 「**実地に**調査」「事業所に**立ち入り**、帳簿書類を検査」「臨検」 | カメラ・センサー・リモート監視による代替を阻む |
| C03 | 書面・文書の交付/提出 | 「書面により」「文書をもって」「〜書を提出」 | 電磁的代替の明文特例がない法律では紙が原則に |
| C04 | 原本・謄本・正副・部数 | 「正本及び副本を提出」「写しを添えて」「各一通」 | 「原本」「副本」概念がデータに素直に対応しない |
| C05 | 押印・署名・印鑑 | 「記名押印」「署名し、印をおさなければ」「連署」 | 電子署名の読み替えが自動には及ばない領域が残る |
| C06 | 備置き・閲覧・縦覧 | 「事務所に**備え置き**、請求があったときは**閲覧**させ」「公衆の**縦覧**に供し」 | 情報アクセスが「その場所へ行く」ことに固定 |
| C07 | 物理掲示・標識 | 「**見やすい場所**に掲示」「標識を掲げ」 | ウェブ掲載による代替を阻む |
| C08 | 公告方法の媒体限定 | 「**官報**に掲載」「**日刊新聞紙**に掲載」「掲示場に掲示」 | 電子公告・ウェブ公示が使えない |
| C09 | 携帯・提示 | 「証明書を**携帯し**、請求があったときは**提示**」「呈示」 | モバイル証明書による代替を阻む |
| C10 | 常駐・専任 | 「事業所**ごとに**〜を置かなければ」「専任の」「常時〜配置」 | 遠隔管理・兼任・巡回による代替を阻む |
| C11 | 定期検査・点検の頻度固定 | 「毎年一回、定期に」「〜年ごとに検査を受け」 | センサー常時監視等リスクベース移行を阻む |
| C12 | 講習・実習の受講義務 | 「〜が行う講習を受け」「実技」 | 開催方法無指定＝集合対面が運用上の前提に |
| C13 | 記録媒体・技術の名指し | 「磁気ディスク」「磁気テープ」「ファクシミリ」「電子計算機」 | 技術陳腐化（フロッピーディスク問題の本体） |
| C14 | 郵便・物理送達 | 「郵便又は信書便により」「書留」「交付して送達」 | 電子送達による代替を阻む |
| C15 | 口頭・読み聞かせ | 「これを**読み聞かせ**」「**口頭で**」「口述を筆記」「朗読」 | 非同期・電子的な内容確認を排除 |
| C16 | 収入印紙・現金納付 | 「手数料は収入印紙をもって」「現金で納付」 | 電子納付を阻む |
| C17 | 経由提出（窓口リレー） | 「都道府県知事**を経由して**提出」「事業主を経由して申出」 | 紙リレー前提の行政ルーティング。ワンスオンリーを阻む |
| C18 | 持参・その場交付 | 「持参」「引渡し」「交付を受けた後でなければ〜してはならない」 | 有体物の物理移動が手続の前提に |

C15・C17・C18 や C01 の「面前」「立会い」は、従来のキーワード型見直し（対面・フロッピー等）では網に掛かりにくい
**「隠れアナログ規制」**の代表例。

さらにLLM発見パス（③参照）で見つかった7概念を v0.2 として追加した:

| # | 概念（v0.2で追加） | 発見の契機となった書かれ方 | ヒット |
|---|------|------|------|
| C19 | 会議体・総会・期日の開催前提 | 「半数以上が**出席する総会**」「審理期日を開き**呼び出さ**なければ」 | 1,015条/199法 |
| C20 | 所在地管轄・場所拘束 | 「所在地**を管轄する**知事に提出」「市町村長**を経て**」 | 1,256条/373法 |
| C21 | 物品への物理表示・刻印・封印・証紙 | 「検査済**証印**を**刻付**」「遺言書の**開封**」 | 197条/70法 |
| C22 | 手帳・証票の発行・返納・往復運用 | 「被保険者証を添付→**券面に記載**して**返付**」「**返納**しなければ」 | 803条/332法 |
| C23 | 供託・営業保証金の予託 | 「最寄りの**供託所**に供託」「営業所ごとに営業保証金」 | 471条/121法 |
| C24 | くじ・発送/到達時刻による決定 | 「願書の**発送の日時**の先後」「公正な方法で**くじ**」 | 48条/25法 |
| C25 | 券面・無記名証券前提 | 「新株予約権**証券と引換えに**」「無記名式」 | 387条/70法 |

### キーワードに現れない「隠れアナログ規制」の実例（スキャンから）

- **民法853条・871条**: 後見の財産調査・計算は後見監督人の「**立会いをもってしなければ、その効力を生じない**」——遠隔立会いの可否が条文上不明。
- **民法465条の6**: 事業保証の公正証書は公証人が「口述を筆記し、これを**読み聞かせ**」——音声・同期・同所前提。
- **公証人法30条・52条**: 「証人を**立ち会わせ**」「その**面前において**署名させ」。
- **健康保険法43条の2**: 保険者への申出は「**事業主を経由して**」——本人→システム直結を阻む紙リレー設計（507箇所で「を経由して」がヒット）。
- **労働基準法106条**: 就業規則等は「常時各作業場の**見やすい場所へ掲示**し、又は備え付け」（書面交付等の選択肢はあるがウェブ完結は省令頼み）。
- **公有水面埋立法3条**: 「書面及関係図書ヲ…**三週間公衆ノ縦覧ニ供シ**」——旧仮名の戦前法はキーワード検索から最も漏れやすい層。

## ③ LLM判定の結果（並列エージェント10体）

詳細は `results/llm_verification.md`。要点:

**検証パス（18概念×16条＝287件の真陽性判定）**
- 候補網の適合率は概念により **25%〜81%**（全体51%）。官報公告(C08)・経由提出(C17)・書面交付(C03)は81%と高く、
  そのまま一括改正候補の母集団に使える。低適合率の概念は偽陽性の型が明確（「副本部長」誤ヒット、「常時勤務」の定義語用法、
  罰則条の混入等）で機械フィルタで改善可能。
- 真陽性145件中 **61%が「デジタル化可能性 high」**。lowは刑事手続の身柄・危険物の実物検査・遺言の真意確認など
  物理性自体が保護法益のもの（9件）に限られる。
- 代表的な high 判定: 民法853条（後見監督人の立会いなしに財産調査は無効）、戸籍法33条（証人の署名）、
  会社法820条（債権者異議公告が官報限定）、労働安全衛生法45条（頻度固定の定期自主検査）、
  実用新案法54条（手数料は特許印紙で納付）、公的個人認証法3条の2（**電子証明書の発行申請が窓口経由**）、
  建設業法39条の4（**電子化特例が「磁気ディスク提出」前提で陳腐化**）など。
- **立法格差の検出**: 同型の手続なのに、信託法・投信法は電磁的議決権行使を手当て済み、農住組合法50条は未手当て——
  という「横並びの穴」が系統的に見つかる。

**発見パス（未ヒット400条の精読→新概念の発見）**
- 54件の発見から **7つの新概念（C19〜C25）** を採用し再スキャン→ **4,177条の新規候補**を追加検出。
  会議体開催前提（1,015条）、所在地管轄（1,256条）、手帳・証票の往復運用（803条）など、
  いずれも従来のキーワード型見直しではゼロヒットの層。
- 採用見送り分（場所固定の許可、執行場所の限定、店舗前提の定義、同時申請、「記載」限定、無資料口頭陳述等）も
  `results/llm_discoveries.json` に記録。

## 限界と次の一手

1. **省令・政令が未収録**: アナログ規制の物量は省令層（様式・手続細目）に集中する。e-Gov API v2（`laws.e-gov.go.jp/api/2/`）が
   使える環境で `--all-law-types` 相当の全種別に同じパイプラインを回すべき。
2. **候補網は再現率重視**: 正規表現層の適合率は概念により5〜9割（LLM検証参照）。本命は「候補網→LLM全件判定」だが、
   今回は費用対効果からサンプル判定に留めた。全20,002件のLLM判定は1件あたり数百トークンで現実的に可能。
3. **「アナログであること」と「改めるべきこと」は別**: 刑事手続の身柄拘束、危険物の実物検査、遺言の真意確認など、
   物理性それ自体が保護法益であるものは digital_potential=low として区別している。
4. 条文の鮮度は2025年5月時点のミラー準拠。直近の改正は未反映の可能性がある。

## 元データの展開と再現手順

```bash
scripts/fetch_laws.sh                            # → data/laws/（法令XMLは非同梱）
python3 scripts/extract_corpus.py data/laws data/articles.jsonl
python3 scripts/scan_concepts.py concepts.json data/articles.jsonl data/findings.jsonl data/summary.json
python3 scripts/aggregate.py data/findings.jsonl data/summary.json results
python3 scripts/join_items.py . data/articles.jsonl results/items.json
python3 scripts/build_fix_list.py . docs/html/fix-targets.html
```
